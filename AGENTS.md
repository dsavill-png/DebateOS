# DebateOS repository instructions

Read PLANS.md and the assigned work order before beginning. The project owners authorize work and decide product priorities. Chat serves as leadership and technical lead. Work investigates questions and records evidence. Codex implements authorized engineering work, verifies it, and prepares changes for review.

GitHub is authoritative for source code, engineering history, and work orders. Dropbox is the durable home for architecture, research, product notes, data references, and handoffs. Link to the authoritative record when information crosses systems. Keep credentials and restricted data out of commits and work orders.

Start work after a human assigns an approved work order. Follow its scope and acceptance criteria. Record a blocker when required permissions, source material, or decisions are missing. Keep changes focused, verify through normal entry points, and report what was tested and what remains unverified.

Record implementation evidence in the task and associated pull request. Chat reviews the result against acceptance criteria and the owner decides acceptance. Task updates and worker starts are manual.
