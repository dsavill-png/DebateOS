# TASK-017 durable person relationship schema

[Migration 0002](../../drizzle/0002_durable_person_relationships.sql) adds evidence-backed person roles, chapter affiliations, scoped student identity assertions, and entry-person membership assertions. A role or affiliation carries optional effective bounds and an observation date. Capture time records when the source was observed. A known start with an unknown end does not establish continuous activity. The role list is a named database constraint that can be extended in a reviewed migration.

Each role, affiliation, and student identity assertion is keyed by its evidence ID. Entry membership assertions are keyed by evidence, entry, and person. A student-backed membership references the exact student-person candidate by composite foreign key. Multiple sources can corroborate the same entry-person pair while retaining their evidence IDs. Consumers counting logical memberships should group by entry and person.

Public role and affiliation projections require matching person and chapter links where applicable. The affiliation names the durable chapter. An approved writer must validate any supporting tournament-school mapping before writing the assertion. Student identity assertions require explicit source evidence or a validated crosswalk. They preserve rejected, conflicting, and unresolved assertions. The public as-of function considers public evidence available by capture time. It returns at most one verified candidate per student and leaves competing or disputed candidates unresolved. A newer rejection supersedes older support for that candidate, while equal timestamps preserve ambiguity.

Relationship projections reuse the public evidence filter and check ancestors linked through `parent_evidence_id`. A public student-backed membership requires matching public roster evidence and verified public identity evidence, plus resolution to that same person at query time. A direct membership requires an explicit `entry-person` evidence link. Keep base assertions restricted. A role granted access to the public membership view also needs SELECT on `public_student_person_assertions` for the invoker-rights resolution function. There are no deployment grants in this migration.
