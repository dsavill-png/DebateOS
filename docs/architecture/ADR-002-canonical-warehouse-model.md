# ADR-002 · Canonical tournament warehouse

**Status** Proposed, pending Dennis and Jared review  
**Date** 2026-11-23  
**Work order** [TASK-010](../../tasks/010-canonical-warehouse-model.md)

## Decision

Build the first warehouse around public Tabroom competition and participation evidence. Maintain separately authorized enrichment for protected data. Model source observations before promoting any assertion to a shared fact. This supports field, pairing, assignment and standings analysis while leaving decision and identity gaps visible. This is a logical design. Physical constraints, PostgreSQL migrations and ingestion changes require a separate approved work order.

The [public inventory](../research/tabroom-public-data-inventory.md) and [authenticated discovery](../research/tabroom-authenticated-access.md) establish the source coverage. The current adapter's approved anonymous reads remain tournament REST, invite REST and structured bulk export. The field endpoint corroborates entry IDs but adds no runtime dependency.

## Entity and relationship catalog

Keys below are logical. Source identifiers are typed by entity and namespaced by provider. Child keys include their indicated owner scope. Preserve raw values and normalize only verified ID representations, such as an integral number and its equivalent decimal string. A scoped key can have many observations over time. A resolved relationship requires an explicit field or validated source containment, consistent scope, and one unambiguous target. Retain unresolved references and conflicting evidence separately from accepted links.

| Entity | Grain, logical key and relationships | Source and evidence |
| --- | --- | --- |
| Tournament | One per tournament ID. Owns zero or more categories, schools and timeslots. | REST tournament, invite and bulk root, with matching IDs. Calendar IDs and webnames are separate references. |
| Category and event/division | Category per tournament and category ID. Event per tournament and event ID, with an evidenced category when available. Category has many events. Event has many entries and rounds. | Invite and bulk categories and nested events. Abbreviations are scoped lookup labels. Keep NSDA category as its own reference. |
| Tournament school and chapter | School per tournament and school ID. Optional chapter link. One chapter can link to multiple schools across tournaments. | Bulk schools and explicit chapter field. Authenticated school and chapter assertions retain their access scope. |
| Entry and durable team | Entry per tournament and entry ID, with one resolved event and one resolved tournament school where supported. An independently identified durable team could have many entries. | Bulk schools and entries, with field corroboration where verified. Preserve active, waitlisted and dropped observations. Entry codes, names and roster similarity supply display context only. Defer the durable team registry and crosswalk until explicit evidence exists. |

| Ballot and score observation | One ballot observation per snapshot, parser version and row pointer, with source ballot ID when supplied. Link validated panel and optionally entry and judge. Score child per ballot observation and array index/pointer. | Bulk ballot rows. Preserve raw side, workflow fields and score array including order, optional score ID, tag and value. Missing and empty arrays stay distinct. |
| Result set, standing and standing value | REST result-set identity per tournament and result-set ID, with verified event reference. Preserve generated/published/bracket fields, rank/place/percentile, raw values and the source result-key definitions. Join result keys only within the source set. Matching labels, ranks or row counts cannot establish a bulk-to-REST set crosswalk. |
| Capture and row evidence | Capture per immutable snapshot ID. Row evidence per snapshot, parser version and JSON pointer, with output role where one row emits multiple observations. Any surfaced link or fact has one or more evidence references. | Public JSON and separately authorized captures. | Publication observation | One assertion per snapshot, subject and publication dimension, supported by pointer or capture-level evidence. | Retain source flags and timestamps separately from fetch time and access state. Round publication, field visibility and standings publication can differ. |
| Account enrichment | One scoped observation per account/grant context, snapshot and row pointer, optionally linked to validated tournament, school, chapter, entry, judge or person keys. | Authorized user tournament, school and judge branches. Coach affiliation, linked judge history and current ballots have separate entitlement contexts. Link `me` and `mine` only through explicit validated identifiers. |

Reserve debate decision and winner facts until side interpretation, explicit vote/decision, multi-judge aggregation, bye, forfeit and correction rules are verified. Event placement stays at result-set grain. Raw judging history labels and vote fields carry the same semantic limits.

## Snapshot, replay and serving policy

Retain authorized source bytes in scope-controlled storage when retention permits. Use a sanitized route and parameters plus a grant reference for protected captures. Keep credentials, cookies and contact data out of analytical rows and repository fixtures. A retry of the same capture operation reuses its capture identity. A later fetch gets its own timestamp and snapshot even when bytes match. Deduplicate immutable bytes only within the same access partition. Replay against the same snapshot and parser version is idempotent. Parser upgrades produce separately traceable observations. Fixture digests and pointers refer to fixture bytes. Source digests and pointers refer to original bytes.

Record capture outcomes independently of publication and entity state. Distinguish observed values, explicit empty responses, omitted fields, not requested, evidenced unpublished, unauthorized/expired, forbidden, ambiguous not-found, invalid response and transient failure. Carry verification states such as verified, unresolved and conflicting. A failed or narrower capture cannot erase a prior observation or prove withdrawal. As-of views use eligible evidence captured by the cutoff and a reviewed resolution policy. Retain contradictory observations and resolution history. Use explicit withdrawal evidence to suppress serving while retaining history subject to retention and deletion rules.

Public views use public-eligible evidence only, including every input to joins, aggregates, caches and exports. Protected observations carry authorization class, purpose, audience and grant scope. Check those at capture, storage, access and serving time. Role-dependent joins and their derived outputs inherit the restrictive input scope. A shared identifier alone conveys no access to a protected fact. Task 003 gates backend ingestion. Keep account/coach partitions isolated and use expiring/revocable access, auditable reads and access-aware cache keys.

## College judge paradigm corpus

### Coverage definition

Measure the distinct Tabroom person IDs explicitly linked to tournament judge records with structured evidence of assignment to a panel in a verified collegiate debate event, within approved season windows. Track category-rostered judges separately as a broader candidate pool, including judges with no observed assignment. A category shared with non-collegiate events cannot by itself establish collegiate participation. Record each inclusion or exclusion and its source, event, season and classification rationale in a versioned manifest. Document discovery gaps, unpublished data and off-platform coverage. Start with one closed season of college policy debate, consistent with DebateOS's initial product scope. Dennis and Jared should choose exact dates, circuits, divisions and expansion to other college formats.

### Live production enumeration

On November 23, 2026, the [production IndexCards OpenAPI v1.2.0](https://api.tabroom.com/v1) matched the approved pin, SHA-256 `e01682f296589c599f6390127ef06a6c9fb10f8c6ab3019a700727322bd7e375`. It advertises cookie-authenticated `GET /rest/paradigms` with optional `search`, `limit` (default 50, range 1–100) and `offset` (default 0). The response is an array of search matches. The contract provides no unfiltered enumeration guarantee, stable ordering, continuation token or total count. Three anonymous production requests returned 401 problem JSON: omitted search at offsets 0 and 1 with limit 1, and empty search at offset 0 with limit 1. Prior authenticated evidence is one numeric search for 366665 with limit 1 returning an empty array, plus successful person-keyed detail and history. **Search pagination is documented. Safe authenticated global listing remains unverified.** An anonymous 401 does not resolve authenticated behavior. Prerelease behavior supplies no production evidence.

If Tabroom confirms this use is supported, validate with a legitimately scoped session and single-row requests: compare omitted and empty search with a vendor-approved known-positive search at offset 0, compare offsets 0 and 1 and repeat offset 0 for stability. Record status, shape, row count and restricted comparison evidence. This can distinguish search behavior and detect an ignored offset. A complete enumeration claim also needs vendor-confirmed scope, filtering, stable traversal and permitted use. Even a working global listing would still need tournament-based eligibility.

### Acquisition and measurement

1. Freeze the season and event manifest. Discover candidates via structured public `/rest/tourns` using documented date bounds, circuit, limit and offset. Compare with approved season lists, log pagination boundaries and gaps, deduplicate tournament IDs, and verify collegiate divisions through structured metadata or leadership classification. Upcoming calendar and account affiliations provide supplemental leads. Validate roster export visibility per tournament. Use no HTML scraping.
2. Read eligible structured exports where available. Collect category-rostered IDs and event-specific panel-assigned IDs separately. Apply explicit judge-person evidence within tournament scope, fill authorized gaps only through structures that explicitly link both IDs, and record linkage failures. Account tournament and judge-history structures are account-scoped. Person-keyed `/record` can corroborate activity of an already linked person, with event labels and votes retained as observations. It cannot discover unknown person IDs or prove a panel join by name.
3. Keep unlinked judge IDs in coverage counts and retain conflicts without choosing a winner by recency or majority. Exclude conflicted paths from acquisition until reviewed. Deduplicate accepted links by person ID within each permitted access partition. If authorized, fetch one keyed paradigm detail per eligible person per initial pass, then apply an approved refresh cadence and request budget. A validated empty paradigm is distinct from 401, 403, ambiguous 404 and parse or transport errors. A stale source review date and a stale fetch are different. Label both against approved thresholds, preserving unknown freshness where dates are absent.
4. A read-only count of the [public Harvard export](https://www.tabroom.com/api/download_data.mhtml?tourn_id=40923) at 2026-11-23 15:50 UTC found 136 distinct judge IDs in Open category `109220`, and 127 distinct judge IDs on Open event `389106` ballot rows. ### Restricted entities and version history

| Entity | Grain and key | History and serving |
| --- | --- | --- |
| Corpus scope and event membership | Scope version and event key, with season, inclusion status and evidence. | Immutable manifest revisions and repeatable coverage reports. |
| Judge eligibility evidence | Scope version, event, scoped judge, evidence ID. Optional resolved person. | Keep roster and assignment basis, link resolution and provenance. Project distinct eligible persons per scope and access partition. |
| Paradigm capture | Person ID plus capture ID, with snapshot ID, UTC time, source route, authorization class and grant scope. | Record outcome and pointers even if no content version was produced. Validate response person ID before attaching evidence. Repeated reads preserve observation history. |
| Paradigm version | Person ID, access partition and version ID. Store sanitized content where retention is permitted or hash-only otherwise. Record SHA-256, sanitization version, source review/update dates if supplied, certification observations and supporting captures. | An unchanged revision links to the existing current version. A change in content, review metadata or certifications creates an immutable subsequent revision with predecessor, first-seen capture and changed fields. Reversions are timestamped transitions. Missing or denied captures do not overwrite revisions. |
| Certification observation and judging history | Certification per paradigm version and verified source ID or certification pointer. History row per person, snapshot and source pointer. | Preserve source label, dates and values when exposed. Keep history separate from paradigm revisions and judge decisions. |
| Derived tendency | Person ID, feature definition/version and derivation run ID, referencing exact input versions and evidence. | Record model/rule version, generation time, sample size and uncertainty. Carry the input access scope through serving, caches and exports. |

Paradigm text, certifications, history and derived outputs are authenticated enrichment. Public republication, sharing, retention, text indexing and use for model processing require applicable authorization. Preround dossiers can show an authorized judge's self-described preferences, review date and source evidence, plus separately labeled tendencies with sample size and confidence where evidence supports them. Public assignment analytics can still describe panel coverage and repeat assignments from public lineage. Treat self-description and verified historical behavior as different evidence. Keep outcome-based tendencies deferred until decision semantics are verified. Revocation and authorized deletion must cover versions, indexes, caches and derived artifacts as applicable.
