# 001 · Tabroom integration feasibility

**Status** Draft, pending approval and manual assignment  
**Worker** Work  
**Review** Chat with the project owners

## Objective

Determine whether DebateOS can obtain the records needed for a small Tabroom integration pilot through a supported, authorized source.

## Scope

- Confirm which debate records the owners need for the pilot and identify the minimum useful field set.
- Check first-party documentation and owner-provided examples for supported APIs or exports. Record availability, authorization requirements, limits, and any restrictions on use or storage.
- Map fields from one approved sample to a proposed DebateOS record, identifying stable identifiers, missing fields, and fields that require human review.
- Record unresolved questions, including any approvals needed before obtaining representative data. Implementation, scheduled collection, and production data storage are outside this order.

## Deliverable

Prepare a feasibility memo for Dropbox Research and link it from this work order. Include source links and verification dates, the sample field mapping or the reason it is blocked, and a recommendation to proceed, revise the scope, or pause.

## Acceptance criteria

- Each proposed access route has a source and an explicit authorization status.
- The memo links an approved sample and documents its mapping, or records the exact sample/access dependency.
- The recommendation names the proposed pilot input, verification method, and decisions required before Codex begins.
